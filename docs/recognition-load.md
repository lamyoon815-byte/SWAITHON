# 자동 촬영 요청과 부하 확인

확인일: 2026-11-04 (한국 시간). FE README 9.2 요청에 따른 BE 구현 검증 기록입니다.

## 호출 계약

- 사진 `POST /recognize`, `mode=artwork`: 사용자당 슬라이딩 60초에 60회. 정상적인 1~2초 간격 호출을 허용합니다.
- 사진 처리 전체(정규화, 품질 검사, CLIP, 최고 후보 위치 추정)는 프로세스당 1개만 실행합니다. 추가 요청은 대기열에 쌓지 않고 즉시 503, `Retry-After: 2`로 반환합니다.
- 횟수 초과는 429, `Retry-After: 60`. 웹에서도 헤더를 읽을 수 있도록 CORS expose_headers에 Retry-After를 지정했습니다.
- FE는 이전 응답 완료 후 다음 촬영을 예약합니다. 429/503이면 해당 시간만큼 대기하며 확인 시트·화면 이동·백그라운드에서는 중단합니다.
- 명패는 Gemini 비용·한도 때문에 자동 반복하지 않습니다. `/analyze`, 명패 `/recognize`, `/correction`의 사용자당 5회/분 공유 제한을 유지합니다.
- 제한은 단일 프로세스 기준입니다. 현재 Docker 실행은 worker 1개이며, 여러 worker/인스턴스를 도입할 때 사용자별 제한은 공유 저장소로 옮겨야 합니다.

## 확인 결과

계약 테스트에서 다음을 확인했습니다.

- 시간을 1초씩 진행시킨 65회 연속 사진 요청이 모두 200.
- 동일 윈도 초과 시 429와 Retry-After 반환.
- 추론 중 겹친 요청은 503과 Retry-After 반환. 실패한 추론도 처리 슬롯을 반환하며 다음 요청이 성공.
- 기존 명패·분석·보정·회원 인증 테스트 통과.

실제 CLIP 모델을 사용한 로컬 순차 처리 측정:

| 조건 | 값 |
|---|---|
| 환경 | macOS arm64, Python 3.12.16, CPU, torch 스레드 2개 |
| 모델 | ViT-B-32-quickgelu / openai |
| 카탈로그 | 모나리자 1점 |
| 입력 | 등록 원본 459 × 527. 실제 휴대폰 촬영본 아님 |
| 측정 범위 | 전처리 + 품질 검사 + 실제 CLIP 인코딩/검색 + ORB/RANSAC 위치 추정 |
| 실행 횟수 | 8회 (첫 실행 1회 + 준비 후 7회) |
| 첫 실행 | 3.646초 (앞선 실행에서는 5.571초) |
| 준비 후 중앙값 / 최댓값 | 0.0409초 / 0.0425초 |

재현 명령(카탈로그·CLIP 인덱스·모델 설치 필요):

```sh
Backend/.venv/bin/python -m Backend.benchmark_recognition --iterations 8
# 배포 서버에서 실제 촬영본으로 반복 측정
Backend/.venv/bin/python -m Backend.benchmark_recognition --iterations 100 --image /path/to/capture.jpg
```

위 결과는 로컬 계산 지연 측정입니다. HTTP 업로드·실기기 촬영 지연·네트워크·여러 관람객의 처리량은 포함하지 않습니다.
배포 서버 CPU, 20점 카탈로그, 휴대폰 1024px 촬영본, 예상 동시 사용자 수로 추가 측정해야 합니다.
현재 자료만으로 배포 서버에서 모든 동시 사용자에게 1초 응답을 보장할 수 없습니다.
첫 모델 로딩도 1~2초를 넘길 수 있으므로 최초 요청 동안 촬영을 겹치지 않고 기다려야 합니다.

## 인식·위치 정확도

- confidence의 실제 촬영본 보정 자료가 없어 기준 환경변수는 기본 공란입니다. 후보가 있으면 medium이며 high는 비활성입니다. 후보 없음은 low입니다.
- 위치 추정은 원본과 촬영본의 충분한 특징점 대응·RANSAC 기하 검증이 있을 때만 bbox와 방향 힌트를 제공합니다.
- 위치가 알려진 합성 촬영본에서 bbox와 방향을 검증했고, 단색·관련 없는 이미지에서는 null을 확인했습니다.
- 실제 전시 조명·반사·가림·반복 무늬에서 위치 정확도는 별도 평가가 필요합니다. 위치를 얻지 못하면 잘못된 안내 대신 null을 반환합니다.
- 해설 영역 연결은 Gemini 스키마 및 카탈로그 등록 시 검증합니다. 기존 해설은 연결이 없으면 region_index=null이며, 실제 검수로 연결을 보완합니다.
