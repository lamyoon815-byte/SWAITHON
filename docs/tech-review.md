# 기술 검토 및 구현 계획

> **2026-11-03 갱신:** AI 담당자의 답변과 회원가입·로그인 포함 결정을 반영하고, 로컬 개발 환경·카탈로그 등록 규격을 재확인했습니다.
> 이 문서의 **목표 규격**, **현재 구현**, **확인 필요**를 구분해서 읽어 주세요.
> AI 프로필 전용 API, JSON 검증 1회 재시도·기본 문구, 설정형 CLIP 임계값 분기를 구현했습니다. AI 보정 함수와 실제 CLIP 평가값은 아직 필요합니다.
> 기존 FE의 iOS 검증 기록은 4.1에 유지합니다. 새로운 기능·규격까지 검증됐다는 뜻은 아닙니다.

## 1. 결정 사항

| 항목 | 결정·현재 상태 |
|---|---|
| 회원 인증 | **회원가입·로그인·로그아웃을 포함**합니다. 이메일·비밀번호 방식으로 BE 구현 완료. 세션은 만료·폐기 가능한 Bearer 토큰입니다. |
| 사용자 데이터 | 시각 프로필과 관람 기록·당시 보정 설정을 **서버의 회원 계정에 연결해 저장**합니다. 기기 저장소는 캐시 용도로 사용할 수 있습니다. FE 연결은 미완료입니다. |
| 작품 입력 | 작품 사진 또는 명패 촬영을 지원하는 BE 경로가 있습니다. 음성 촬영 안내·자동 촬영은 제외합니다. 명패의 외부 API 사용 범위는 2장에서 확인합니다. |
| 보정 대상 | 등록 작품은 DB에 등록한 원본을 보정의 바탕 이미지로 사용합니다. 미등록 작품은 촬영본을 사용합니다. |
| 보정 실행 위치 | 기존 **앱 Skia 실시간 보정**을 유지하며, AI 함수 연동용 서버 `POST /correction`도 준비했습니다. 실제 AI 함수는 미연결로 503을 반환하며 FE 사용 위치는 별도 조율합니다. |
| 확대 | 앱의 핀치 줌과 확대·축소 버튼으로 제공합니다. |
| 등록 작품 해설 | **미리 생성 → 팀 검수 → DB 저장 → 조회**합니다. 시연 때 등록 작품의 해설 조회가 실시간 Gemini 응답에 의존하지 않도록 합니다. |
| 미등록 작품 해설 | 실시간 Gemini 분석을 사용하며 **작품 제목·작가를 추측하지 않습니다.** 인식이 거부된 촬영본으로 시각적 해설만 제공합니다. 미등록 거부 기준은 평가 후 적용합니다. |
| Gemini 기본 모델 | AI 담당자가 제안한 **`gemini-3.1-flash-lite`**를 채택 대상으로 기록합니다. 실제 사용은 서버 `GEMINI_MODEL`에 설정하고 호출 검증해야 합니다. |
| 모델 품질 대안 | AI 제안은 `gemini-3.5-flash`입니다. 공식 문서는 현재 해당 ID를 3.6으로 연결하므로, 실제 대안 ID·품질·비용은 다시 확인합니다. |
| 촬영본 보관 | 사용자 촬영본은 요청 처리에 필요한 임시 파일·메모리를 사용한 뒤 정리하고 영구 저장하지 않습니다. 카탈로그 원본과 구분합니다. |
| 이번 마감 제외 | **SuperPoint·LightGlue, PaddleOCR, 파인튜닝**은 제외합니다. 기존 CNN·MLP 학습 아이디어를 이번 마감의 확정 구현으로 내세우지 않습니다. |

## 2. 확인이 필요한 경계

| 항목 | 기존 구현·제안의 차이 | 확인할 내용 |
|---|---|---|
| 보정 실행 위치 | FE는 Skia 실시간 보정, AI는 JPEG를 반환하는 Python 함수 제안 | AI 함수가 검증·비교용인지, 서버에서 실행할 서비스 함수인지 FE·AI와 결정합니다. 합의 전까지 기존 앱 보정 기준을 유지합니다. |
| 명패 인식의 Gemini 사용 | 현재 BE는 명패를 Gemini로 읽습니다. AI 답변은 실시간 Gemini를 미등록 작품에만 사용한다고 표현했습니다. | 이 제한이 **해설 생성에만 해당하고 명패 읽기는 예외**인지 확인합니다. 예외를 확정하기 전까지 명패 인식의 오프라인 시연 가능성을 보장하지 않습니다. |
| 밝기 단위 | 새 AI 규격은 -50~50, 현재 BE는 -1~1, FE 검증 슬라이더는 -0.3~0.3 | AI 알고리즘에서의 수학적 의미와 FE 매핑을 정합니다. 단순 배율을 임의로 적용하지 않습니다. |
| 최초 프로필 | `color_type`, `severity`의 기본값·미설정 상태는 AI 답변에 명시되지 않았습니다. | 가입만으로 색각 검사 결과가 normal이라고 판단하지 않도록 초기 상태를 합의합니다. |
| Gemini 기본 문구 | 해설 JSON 검증 실패 시 1회 재시도 후 기본 안내와 `fallback=true`를 반환합니다. | HTTP 오류는 별도 유지합니다. 명패는 실패 시 502이며, 사전 생성 스크립트는 기본 문구를 저장하지 않습니다. |
| CLIP 미등록 분기 | `CLIP_MATCH_THRESHOLD` 설정 시 최고 점수가 기준 미만이면 `no_match`와 빈 후보를 반환합니다. | 실제 기준값은 AI 평가 결과로 설정합니다. 미설정이면 기존 후보 확인 방식입니다. |

## 3. AI 인터페이스와 데이터 규격

### 3.1 시각 프로필 — AI 규격 및 전용 저장 API

| 필드 | 허용 값·범위 | 답변에 명시된 기본값 |
|---|---|---|
| `color_type` | `normal`, `protan`, `deutan`, `tritan` | 사용자 설정 시작값 `normal` |
| `severity` | 0.0~1.0 | 사용자 설정 시작값 0 |
| `contrast` | 0.5~2.0 | 1.0 |
| `brightness` | -50~50 | 0 |
| `sharpness` | 0.0~2.0 | 0 |
| `edge` | 0.0~1.0 | 0 |

`GET /me/ai-profile`은 미설정 시 `null`입니다. `PUT /me/ai-profile`은 아래 6필드를 별도로 저장하며 생략 필드는 아래 시작값으로 채웁니다. 이는 색각 검사 결과가 아닙니다.

```json
{
  "color_type": "normal",
  "severity": 0.0,
  "contrast": 1.0,
  "brightness": 0,
  "sharpness": 0.0,
  "edge": 0.0
}
```

**현재 BE API와의 차이 — 코드 이행 전**

| 현재 BE 필드 | 새 AI 필드 | 이행 시 확인할 사항 |
|---|---|---|
| `color_vision` | `color_type` | `protanopia/deuteranopia/tritanopia`를 `protan/deutan/tritan`으로 매핑 |
| `color_severity` | `severity` | 의미·기본값·미설정 상태 합의 |
| `sharpen` | `sharpness` | 이름 변경과 FE 연결 |
| `brightness` (-1~1) | `brightness` (-50~50) | 값의 의미와 변환 규칙 합의 |
| 없음 | `edge` | 필드 추가 및 FE 윤곽선 강조 구현 연결 |
| `contrast` | `contrast` | 범위·단위 유지 확인 |

현재 `/me/profile`은 기존 필드 형식을 유지하고, `/me/ai-profile`은 AI 6필드 형식을 별도로 저장합니다. 위 JSON은 `/me/ai-profile`로 보내며 `/me/profile`과는 호환되지 않습니다.
`strength`, `zoom`, `narration_mode`, `speech_rate`, `high_contrast`는 기존 회원 프로필의 앱 설정입니다.
AI 보정 함수의 6개 입력 필드와 구분해 보존·적용 방식을 맞춥니다.

### 3.2 AI 함수

```text
correct_image(image, profile) -> corrected_jpeg
describe_artwork(image, mode, artwork_info=None) -> description_json
```

- `correct_image`: 입력 이미지와 **같은 크기**의 JPEG를 반환하는 것이 AI 제안입니다. 현재 BE의 JPEG 형식 통일은 개인 맞춤 보정 구현과 별개입니다.
- `describe_artwork`: 미등록 작품은 `artwork_info=None`으로 전달하고 작가·제목·연대를 추측하지 않습니다. 등록 작품의 사전 생성에는 DB 정보를 근거로 전달합니다.
- `POST /correction`의 서버 연결 계약은 동기 `correct_image(image: bytes, profile: dict) -> bytes`로 정했습니다. RGB JPEG 바이트를 전달하며, 같은 크기의 JPEG 바이트를 받아 검증합니다. AI 담당자는 이 계약으로 함수를 구현하거나 어댑터를 제공해야 합니다.
- 모드 후보는 현재 BE의 `facts`, `interpretations`, `both`입니다. AI 함수의 실제 허용 값은 확인 후 맞춥니다.
- AI 코드 위치는 **`Backend/ai/`**, 공용 해설 Pydantic 모델은 **`Backend/catalog.py`의 `Description`, `Region`**을 기준으로 연결합니다.
- 기존 Gemini 호출·타임아웃·호출량 제한은 `Backend/gemini.py`, API 경로는 `Backend/ai_routes.py`에 있습니다. 중복 Gemini 클라이언트를 별도로 확정하지 않습니다.

### 3.3 해설 JSON

```json
{
  "facts": ["실제로 보이는 인물·사물·색채·구도"],
  "interpretations": ["가능한 분위기·감정적 해석"],
  "regions": [{"label": "붉은 꽃", "bbox": [0.05, 0.70, 0.20, 0.25], "color": "붉은색"}],
  "mood_keywords": ["고요", "쓸쓸함"]
}
```

- `bbox`는 현재 BE 기준 **[왼쪽 x, 위쪽 y, 너비, 높이]**, 전체 이미지 대비 0~1 비율입니다. AI 측 좌표 계약·위치 정확도는 확인해야 합니다.
- 원본 이미지 기준인지, 회전 보정된 촬영본 기준인지 입력 경로별로 일치시킵니다. 정확한 영역을 알 수 없으면 빈 배열로 둡니다.
- 새 목표 정책은 **Pydantic 검증 → 실패 시 1회 재시도 → 다시 실패하면 기본 안내 문구**입니다. 의미 없는 사실·감정·영역을 채워 성공한 해설처럼 보이게 하지 않습니다.
- 현재 BE는 Pydantic 검증 실패 1회 재시도와 `fallback` 기본 문구를 구현했습니다. HTTP 오류 재시도를 포함해 요청당 총 2회 이내입니다. 키·한도·시간 초과·연결 오류는 HTTP 오류로 유지합니다.
- 등록 작품은 사전 생성한 JSON을 팀이 검수하고 `review_status=reviewed`로 등록합니다. `pending` 해설은 앱 조회에 노출하지 않습니다.

## 4. 기술 스택과 검증

### 4.0 BE 현재 구현

| 구분 | 상세 내용 |
|---|---|
| Python | **3.12**, 현재 개발 가상환경 **3.12.16** |
| 서버 | FastAPI, Uvicorn |
| 회원 인증 | Argon2 비밀번호 해시, 토큰 해시를 저장하는 7일 Bearer 세션, 로그아웃 폐기 |
| 데이터베이스 | SQLite `catalog.sqlite3`(작품), `users.sqlite3`(회원·세션·프로필·관람 기록) |
| 이미지 처리 | Pillow, pillow-heif로 업로드 검증·회전 보정·RGB JPEG 전처리 |
| 이미지 서빙 | FastAPI StaticFiles로 카탈로그 원본 제공 |
| 작품 검색 | OpenCLIP ViT-B/32 계열 CPU 추론, NumPy 코사인 유사도 검색, `.npz` 인덱스 |
| 현재 모델 설정 | `ViT-B-32-quickgelu` / `openai`. 평가·인덱스 생성·서비스 추론에서 같은 설정을 사용합니다. |
| 명패 매칭 | Gemini 텍스트 추출 연동 코드 + RapidFuzz |
| 키 관리 | `GEMINI_API_KEY`, `GEMINI_MODEL`은 서버 환경변수 또는 `Backend/.env`에서만 관리 |
| 개발·배포 | ngrok 설치·계정 설정 확인 완료, FE 연동 시 터널 실행. Docker 구성 작성. Render 배포는 추후 진행하며 메모리·영속 저장을 검증합니다. |

회원 DB가 생겼지만 현재 구현은 SQLite를 사용합니다. 운영 사양·확장성이 필요해지면 별도로 재평가합니다.
RAM 1.5GB 이상은 초기 검토 기준이며, 운영 사양은 실제 모델 적재·동시 요청 메모리를 측정한 뒤 정합니다.

**현재 주요 API**

```text
POST   /auth/register                  이메일 회원가입·세션 발급
POST   /auth/login                     로그인
POST   /auth/logout                    현재 세션 폐기
GET    /me                            내 회원 정보
GET    /me/profile                    내 시각 프로필
PUT    /me/profile                    내 시각 프로필 전체 저장 (현재 구규격)
POST   /me/history                    관람 기록·보정 설정 스냅샷 저장
GET    /me/history                    내 관람 기록
DELETE /me/history/{id}               내 관람 기록 삭제
POST   /upload                       촬영본 수신·검증·형식 변환 확인
POST   /recognize                    image + mode(artwork|placard) → 후보 최대 3개
GET    /artworks                      작품 목록
GET    /artworks/{id}                 작품 정보·검수 해설·원본 이미지 URL
GET    /artworks/{id}/narration       감상 모드에 맞춘 검수 해설 텍스트
POST   /analyze                       미등록 작품 해설 (Gemini 설정 필요)
```

회원·프로필·기록 및 인식·실시간 분석·맞춤 해설 API는 인증이 필요합니다.
`POST /correction` API를 구현했습니다. 등록 작품 ID 또는 촬영본과 AI 프로필을 받아 JPEG를 반환하는 계약이며, 실제 AI 함수 미연결 상태에서는 503을 반환합니다. 기존 앱 Skia 보정을 대체한 상태는 아닙니다.

### 4.3 모델 관련 공식 문서 확인 (2026-11-02)

- AI 답변의 **`gemini-2.5-flash`가 10월 16일 일괄 종료됐다는 설명은 현재 공식 안내와 다릅니다.** 현재 안내는 과거 사용 이력이 있는 사용자에게 2.5 접근을 제한하며, 별도 공지 전까지 제공을 계속한다고 설명합니다. 프로젝트에서는 신규 사용 모델로 선택하지 않습니다. [종료·접근 안내](https://ai.google.dev/gemini-api/docs/deprecations)
- `gemini-3.1-flash-lite`는 이미지 입력과 구조화 출력을 지원합니다. 채택 제안은 유지하되 실제 키·해설 품질·호출 가능 여부를 검증합니다. [모델 문서](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-lite)
- `gemini-3.5-flash`는 deprecated 상태이며 해당 ID 요청은 `gemini-3.6-flash`로 연결됩니다. 품질 비교에서 정확한 요청 ID와 실제 모델을 기록합니다. [3.5 모델 문서](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash)

## 5. 이번 마감의 구현·데이터 범위

### P0 — 회원 기반 감상 흐름과 시연

1. 회원가입·로그인 및 계정별 시각 프로필·관람 기록을 FE에 연결합니다.
2. 퍼블릭 도메인 작품 **20점**의 메타데이터·고화질 원본과 CLIP 인덱스를 준비합니다. 현재 저장소 데모는 1점입니다.
3. 등록 작품 해설을 미리 생성하고 팀이 검수해 DB에 등록합니다.
4. 등록 촬영본 60장·미등록 사진 10장으로 CLIP을 평가하고 미등록 거부 기준을 전달받아 적용합니다.
5. 등록 작품은 원본·검수 해설을 제공하고, 미등록은 제목 없이 시각적 해설을 제공합니다. 미등록 분석이 작품명 식별에 성공한 것처럼 표시하지 않습니다.
6. 앱의 실시간 대비·밝기·선명도·강도 보정, 원본 전환·확대·TTS를 연결합니다. 새 색각·윤곽선 규격과 Python 함수의 서비스 적용은 합의 후 반영합니다.
7. ngrok으로 실기기 연동을 검증하고, 외부 API 실패·기본 문구 처리와 등록 작품의 시연 경로를 확인합니다.

### 추가 구현·후속 검토

- 영역 터치·색 이름 안내와 분위기 기반 음악은 좌표·데이터·FE 구현 상태에 따라 결정합니다.
- 카탈로그 300~1000점 확대는 기존 확장 목표로 남기되, 이번 초기 평가 20점과 구분합니다.
- 학습 보정 모델과 CLIP 어댑터 등 기존 6장 학습 아이디어는 현재 납품 대상으로 확정하지 않습니다. 심사 기준의 실제 학습 요구는 별도 확인이 필요합니다.
- SuperPoint·LightGlue, PaddleOCR, 파인튜닝, 사용자 피드백 기반 선호 학습은 이번 마감 범위에서 제외합니다.

## 6. CLIP 평가·미등록 거부 기준 전달

- **카탈로그:** 퍼블릭 도메인 작품 20점. 비슷한 작품을 포함할 수 있으며 실제 목록·출처를 기록합니다.
- **등록 평가 사진:** 작품당 실제 촬영 3장, 총 60장.
- **미등록 평가 사진:** 카탈로그에 없는 작품 10장.
- **지표:** 등록 사진 Top-1·Top-3, 등록·미등록의 최고 유사도 분포, 미등록 오매칭률, 등록 오거부율, CPU 추론 응답 시간.
- **환경:** `CLIP_MODEL`, `CLIP_PRETRAINED`, 전처리, 카탈로그 버전·이미지, CPU·메모리 조건을 기록합니다. BE 기본 설정과 다른 가중치를 평가했다면 인덱스도 동일 설정으로 재생성합니다.
- **전달:** 선택한 점수 임계값과 비교 연산(`>=` 등), 후보 간 점수 차이를 함께 쓰는지, 거부·애매한 경우의 분기 예시를 공유합니다. 평가 전 임계값을 임의로 정하지 않습니다.
- 점수는 확률이 아닙니다. BE는 설정형 거부 분기를 구현했으며 실제 임계값은 평가 결과를 받은 뒤 설정합니다. 최고 점수 < 기준값이면 거부하고, 같으면 후보 확인을 유지합니다.

| 평가 항목 | 결과 |
|---|---|
| 등록 사진 수 / 미등록 사진 수 | 예정 60 / 10, 실제 수집 미완료 |
| Top-1 / Top-3 | 미측정 |
| 미등록 오매칭률 / 등록 오거부율 | 미측정 |
| 선택한 거부 임계값·규칙 | 미정 |
| CPU 지연·메모리 | 평가 환경에서 측정 예정 |

## 7. 작품 데이터·해설 운영

- 소스 사이트 전체가 아니라 **개별 작품과 제공 이미지의 퍼블릭 도메인·재사용 조건**을 확인합니다.
- The Met, 시카고 미술관, Wikimedia Commons 등에서 원본 URL·이용 조건을 함께 기록합니다.
- 제목·작가·제작 시기·배경과 이미지가 서로 맞는지 확인하고 작품 ID를 안정적으로 부여합니다.
- 등록 형식과 예시는 [AI 코드·데이터 연동 안내](../Backend/ai/README.md), 실행·등록 상세는 [BE README](../Backend/README.md)를 참고합니다.
- 해설은 `generate_descriptions.py`의 출력 파일을 팀이 검수하고 `review_status`를 `reviewed`로 변경한 후 `import_catalog.py`로 등록합니다. 검수하지 않은 실패 문구는 완료 해설로 승격하지 않습니다.
- 회원 데이터는 작품 데이터와 별도 SQLite 파일에 저장합니다. 계정 프로필 변경이 이미 저장된 관람 기록의 설정 스냅샷을 바꾸지 않도록 합니다.

### 8.1 작품 카탈로그 전달 규격

| 필드 | 형식·등록 규칙 |
|---|---|
| `id` | 필수 문자열. 영문 소문자·숫자로 시작하고 소문자·숫자·`_`·`-`만 사용, 최대 80자. 같은 ID 재등록 시 갱신. |
| `title`, `artist` | 필수, 공백이 아닌 작품명·작가명 문자열. |
| `image_path` | 필수. JSON 파일 위치 기준 상대 경로 또는 절대 경로. JPEG·PNG·WebP 원본. |
| `year`, `background` | 선택 문자열 또는 `null`. 제작 시기·배경 설명. |
| `number`, `museum` | 선택 문자열 또는 `null`. 소장번호·미술관. 번호는 문자열로 보존하며 같은 미술관 내 중복 번호는 거부. 미술관 없는 번호끼리도 중복 불가. |
| `source_url`, `license` | 스키마상 선택 문자열 또는 `null`. 실제 수집 데이터에는 개별 이미지 출처와 퍼블릭 도메인 근거를 기재. |
| `description` | 생성 전 `null`. 생성 후 3.3의 해설 JSON. |
| `review_status` | 기본 `pending`. 팀 검수 후 해설과 함께 `reviewed`로 등록. 해설 없이 `reviewed` 등록 불가. |

복사해서 사용할 JSON 예시와 설치·등록·인덱스 생성 명령은
[AI 코드·데이터 연동 안내](../Backend/ai/README.md)에 있습니다.
`number`, `museum` 지원은 현재 로컬 작업본 기준이며, 원격 반영 여부는 별도 확인해야 합니다.

### 8.2 문서 반영 후 남은 코드 작업

다음 항목은 **문서 반영과 별개로 코드 이행이 필요**합니다.

- 6필드 AI 프로필 전용 저장 API는 구현했습니다. 기존 FE 설정과의 밝기 단위 매핑은 여전히 합의가 필요합니다.
- JSON 스키마 실패 1회 재시도·기본 문구 정책은 구현했습니다. FE가 `fallback` 표시를 연결해야 합니다.
- AI가 전달할 실제 함수와 기존 BE 연동, 모드·입출력 타입 확정.
- CLIP 평가 결과로 `CLIP_MATCH_THRESHOLD`를 설정하고 FE가 `no_match`에서 `/analyze`로 연결해야 합니다.
- 보정 실행 위치와 Gemini 명패 예외 여부 확인 후 API 계약 확정.

API별 요청·응답 및 보정 함수 미연결 상태는 [FE 전달 문서](fe-handoff.md)를 참고합니다. 기존 회원 DB는 서버 시작 시 AI 프로필 테이블과 관람 기록 스냅샷 열을 자동 추가하며 기존 기록은 유지합니다.
