# v2 계산 실행 동등성·처리 시간 확인

[검증 전 계획](execution-plan.md)대로 보정 설정을 바꾸지 않고 메모리 사용과
스레드 실행 설정만 확인했다. 별도 프로세스의 OpenCV·BLAS 스레드는 1이었다.

## 동등성

- 기존 21점 + 추가 12점 × 3유형의 A' 전체 픽셀: 99건 전부 bit-identical.
- v2의 네 평가 모델별 픽셀 쌍 지표: 396건 전부 기존 v2 원자료와 일치.
- 입력당 평균 ΔE: 99건 전부 기존 v2 값과 일치(1e-6 허용).
- 밀밭/적색약, 침실/녹색약, 프로방스 농가/청색약의 최종 전체 픽셀도
  기존 v2 함수와 bit-identical.

## 1000px 입력 63건의 시간

| 실행 경로 | 중앙값 | 최대값 | 3초 초과 |
|---|---:|---:|---:|
| 기본 v2 | 2.073초 | 5.182초 | 9/63 |
| 저메모리 A' + v2, 단일 스레드 | 2.521초 | 4.204초 | 22/63 |

두 경로 모두 A' 계산, 군집화, 픽셀 최적화, 최종 색 변화·자체 검증을 포함한다.
파일 읽기, 비교용 기존 A' 재계산, 최종 평가, JPEG 인코딩은 시간에서 제외했다.
비교용 계산과 동등성 검사는 보정 시간 측정 밖에서 별도로 실행했다.

최댓값 감소만으로 전체 속도가 좋아졌다고 해석하지 않는다. 스레드 설정에 따른
단계별 비용과 데스크톱 부하를 포함한 단일 실행 측정이며 반복 시간 분산은 추정하지 않았다.
최대 3초 기준은 계속 미통과다. 기존 앱·서버 프로세스의 설정은 변경하지 않았다.

별도로 지정하도록 스크립트를 복사해 조정하거나, 기존 측정 자료를 보존한 별도 작업 폴더를 사용한다.
측정 당시 실행 명령은 다음과 같다.

```powershell
$env:PYTHONUTF8 = '1'
$env:OPENBLAS_NUM_THREADS = '1'
$env:OMP_NUM_THREADS = '1'
$env:MKL_NUM_THREADS = '1'
.\Backend\.venv\Scripts\python.exe -m Backend.ai.pixel_speed
```
