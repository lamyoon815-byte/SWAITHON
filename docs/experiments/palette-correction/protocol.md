# 그림별 대표색 보정: 실행 전 평가 계획

고정일: 2026-11-13. 이 문서를 작성한 뒤 21점/검사판의 held-out 결과를 처음 측정한다.
이 실험의 결과를 보고 설정값·모델·성공 조건을 바꾸지 않는다.

## 비교 대상과 방법

- 기준 A': 현재 [서버 보정](../../../Backend/ai/correction.py)의 `correct_array`.
- 실험 B: [별도 모듈](../../../Backend/ai/palette_correction.py)의 k-means++ 초기화와
  Lloyd 반복으로 Lab 대표색 최대 12개를 찾고, Machado 2009에서 구분이 줄어든
  대표색을 projected Adam으로 이동한다. 신경망 학습이 아닌 **비지도 군집화 + 최적화**다.
- 목표는 헷갈리는 대표색 쌍의 차이 회복, 다른 쌍과의 새 충돌 억제, 원본 색 보존이다.
  헷갈리는 쌍에 속하지 않는 대표색은 고정한다. 픽셀은 모든 대표색의 Gaussian 가중치를
  사용하므로 주변 대표색의 영향을 조금 받을 수 있다.
- 설정은 `PaletteConfig` 기본값으로 고정하고 결과에 그대로 기록한다.
- 픽셀 단위 실제 ΔE76을 계산하여 B가 같은 입력의 A' 색 변화 예산을 넘으면
  변화량을 줄인다. 이 예산 계산은 방법의 일부이며 시간에도 포함한다.
- 앱, 기존 `/correction`, 미리보기, 검사판 배포 파일에는 연결하지 않는다.

## 데이터와 측정

- `Backend/catalog.artworks.json`의 21점 전부, 적색약/녹색약/청색약 각각 평가.
- 원본의 긴 변을 최대 1000px로 줄여 보정과 시간을 측정한다. 지표는 보정 후 원본과
  결과를 같은 방법으로 최대 600px로 줄여 계산한다. 입력 해시와 파일 목록을 저장한다.
- 대표색 계산용 표본은 입력에서 최대 12,000픽셀을 고른다. 군집화/최적화 시드 20261112.
- 1차 작품 비교는 보정 세기 1.0. 관찰자 시뮬레이션은 항상 severity 1.0.
- 검사판은 기존 `make_plate`, 글꼴 탐색, 720px 크기 사용. 유형마다 기존 숫자 목록의
  첫 4개와 기존 seed + 판 순번으로 4장씩, 총 12장 생성. A'/B에 같은 RGB와 점 좌표를 사용.
  보정 세기 0.2, 0.6, 1.0을 모두 평가한다. 생성한 원본과 점 목록도 결과에 저장한다.
- 모든 작품에서 같은 고정 시드 20261113으로 픽셀 쌍 30,000개를 뽑아 양 방법을 비교한다.
  보정 전 평가 모델에서 ΔE가 원본 정상 시각의 절반 미만이고 원본 ΔE > 15이면
  손실 쌍이다. 보정 후 절반 이상이면 회복이다. 쌍이 20개 미만인 셀은 참고치로 표시한다.
- 같은 모델/유형의 회복 수 / 손실 쌍 수를 작품 전체에 합쳐 계산한다(micro).
  작품별 단순 평균(macro), 새로 헷갈리게 된 쌍, 인접 경계 회복도 함께 공개한다.
- 평균 색 변화는 원본 대비 CIELAB ΔE76. 1000px 보정 입력의 모든 픽셀로 측정한다.
- 검사판 숫자 선명도는 기존 `number_contrast`: 숫자 점과 바탕 점 평균 Lab의 ΔE76.
  실제 숫자 정답률이나 사용자 시력 측정으로 해석하지 않는다.
- 시간은 이미지 RGB 배열 입력부터 출력까지의 계산 시간이며 파일 읽기/JPEG 인코딩 제외.
  B 시간에는 A' 색 변화 예산 계산 시간을 포함한다. 첫 실행 전 작은 합성 입력으로 준비한다.
  CPU, 라이브러리 버전, 해상도, 방법별 중앙값/최대값을 기록한다.

## 최적화에 쓰지 않는 평가 모델

1. Brettel 1997 + sRGB Smith–Pokorny 1975/Judd–Vos.
2. Viénot 1999 + 같은 원뿔 변환. 청색약은 부정확한 비교용 결과로 따로 표시한다.
3. Vischeck: Brettel + GIMP/Vischeck 원뿔 변환과 anchor.
4. HPE: Brettel + Hunt–Pointer–Estevez. 원래 색순응용 변환으로 **민감도 확인용**이다.

이 네 가지는 완전히 독립된 이론이나 네 집단의 실험 검증이 아니다.
평가 모델의 설정과 수식은 [DaltonLens 구현](https://github.com/DaltonLens/DaltonLens-Python)
및 기존 독립 평가 행렬과 대조한다. 최적화 모듈은 평가 모델을 import하지 않는다.

## 개선 판정: 아래 조건을 전부 통과해야 함

- 네 평가 모델 **각각**, 그리고 각 유형에서 작품 전체 micro 회복률 B > A'.
  손실 쌍이 없는 셀은 개선 근거로 세지 않는다.
- 모든 작품×유형에서 평균 색 변화 B <= A' + 0.000001 ΔE.
- 검사판의 모델×유형×세기별 4장 평균 선명도 B >= A' - 0.001 ΔE.
  개별 판의 하락 수도 함께 공개한다.
- B의 1000px 작품 보정 최대 시간이 **3.0초 이내**(예산 계산 포함).
- 심한 얼룩/색 띠/클리핑 유무를 비교 이미지로 시각 확인한다. 수치 통과만으로 시각 품질을 보장하지 않는다.

하나라도 실패하면 **이번 설정은 개선되지 않았다**고 기록한다. 결과를 본 뒤 변경이 필요하면
다른 버전/계획과 별도 검증 자료가 필요하다. 이 21점은 발표용 고정 비교 세트로,
새 그림 일반화나 실제 색각이상 사용자의 효과를 입증하는 독립 임상/사용성 시험이 아니다.
