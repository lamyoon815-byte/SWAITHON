# 국소 색 변화 제한·처리 시간 검증 v3

> 아래 수치는 고정된 1000px 실험 결과다. 이후 진행한 선택형 서버 연결과 원본 해상도 처리 시간은 [서버 연결 검증](server-integration.md)에 별도로 기록한다. 서버 기본값은 기존 `selective`다.

**3초 처리·픽셀별 색 변화·검사판·기존 A' 대비 회복률 조건은 모두 통과했다.**
장미 그늘과 아기 얼굴·손의 국소 과변색도 확대 비교에서 완화됐다.
다만 회복률은 v2보다 낮다. 기존 21점의 Brettel 기준 A' **57.78% → v2 74.46% → v3 70.99%**다.
v2의 높은 회복률을 그대로 유지한 속도 개선으로 해석하지 않는다.

| 핵심 결과 | 값 |
|---|---:|
| 기존 21점 Brettel 전체 회복률 | 57.78% → 70.99% |
| 이번에 따로 남긴 새 12점 Brettel 전체 회복률 | 49.27% → 72.08% |
| 1000px 최대 처리 시간(63건) | 1.293초 |
| 느린 5건 각 2회 반복의 최대 시간 | 1.171초 |
| 각 픽셀 색 변화 A' 초과(허용 오차 1e-6) | 0건 |
| 개별 검사판 대비 하락 | 0/180셀 |

평가 시작: 2026-11-13 02:08 KST. 코드·설정·입력은 평가 전에 고정했다.

각 픽셀의 원본 대비 색 변화도 기존 A' 이하로 제한했다. k-means로 만든 부드러운 보정 함수를
그림마다 Machado로 최적화한다. 신경망 재학습이 아니다. 앱은 기존 A'를 유지한다.

## 발표 전 확인: 별도 12점의 의미

fresh12는 **색 보정 방식 개발·설정 조정에서 제외한 별도 검증 12점**이다.
기존 작품 인식용으로 보유한 이미지에서 추출했으므로, 새로 수집한 외부 자료나
모든 모델에서 한 번도 사용하지 않은 그림이라는 뜻으로 발표하지 않는다.
v2 때의 추가 12점은 previous12로 분리했으며, 이번 fresh12와 겹치지 않는다.

- 목록 선정 기록: 2026-11-13 01:29:11 KST. 사전에 정한 SHA-256 정렬 규칙으로 12점을 고르고 파일 해시를 기록했다.
- 코드·설정 고정: 02:08:36 KST. 평가 실행 시작: 02:08:40 KST.
- 저장된 v3 개발 비교 4개 자료에는 fresh12 작품 ID가 없고, 기존 33점과 파일 해시 중복도 0건이다.
- 최종 결과에 담긴 고정 기록과 현재 고정 기록이 같으며, 고정한 코드·설정·입력 해시도 다시 일치함을 확인했다.
  결과를 본 후 보정 코드나 설정을 바꾸지 않았다. 이후 수정은 보고서·시각 점검 기록이다.

새 입력에도 k-means와 Machado 기반 최적화는 그림마다 수행한다. 이것은 평가 대상 알고리즘의 처리 과정이다.
분리한 것은 **최적화 목표·반복 횟수 등 공통 설정을 최종 평가 결과에 맞춰 바꾸는 개발 과정**이다.
발표에서는 “색 보정 개발에 사용하지 않은 별도 작품 12점에서도 검증했다”라고 표현한다.

## 회복률

regression21은 기존 21점, previous12는 이미 본 v2 추가 12점으로 둘 다 개발·회귀 자료다.
fresh12만 이번 설정 고정 후 처음 평가한 작품이다. 모든 모델에 같은 30,000쌍을 사용했다.
회복률은 시뮬레이션에서 손실된 색 차이를 정상 차이의 절반 이상으로 회복한 픽셀 쌍의 비율이다.

**전체 값은 세 유형의 백분율을 단순 평균한 값이 아니다.** 작품·유형별 회복 쌍 수를 모두 더하고
손실 쌍 수의 합으로 나눈다. 기존 21점 Brettel의 A'는 다음과 같다.

| 유형 | 회복 쌍 | 손실 쌍 | 회복률 |
|---|---:|---:|---:|
| 적색약 | 11,213 | 16,590 | 67.59% |
| 녹색약 | 9,339 | 12,099 | 77.19% |
| 청색약 | 20,444 | 42,262 | 48.37% |
| 합계 | 40,996 | 70,951 | **57.78%** |

즉 `40,996 / 70,951 × 100 = 57.78%`다. 청색약의 손실 쌍 수가 더 많아 전체 값에서 차지하는 비중도 크다.
v3는 같은 70,951쌍 중 50,371쌍을 회복해 70.99%다.
조건은 같은 기존 21점, 보정·시뮬레이션 강도 1.0, 작품당 같은 난수 시드의 30,000쌍이다.
보정 입력은 최대 1000px이고 픽셀 쌍 평가는 최대 600px로 줄인 이미지에서 수행한다.
정상 시각 ΔE76>15이면서 원본 시뮬레이션의 차이가 정상 차이의 절반 미만인 쌍을 손실로 정의하고,
보정 후 절반 이상이 된 쌍을 회복으로 센다.

가장 느렸던 기존 1000px 5건을 각각 두 번 추가 측정했다. 반복 10건 최대 1.171초.
시간은 RGB 배열 보정 전체다. A' 계산·군집화·최적화·국소 제한·최종 자체 검증을 포함하며 파일 입출력과 최종 평가만 제외한다.
1000px 측정과 512px 원본 측정은 분리했다. 이 컴퓨터의 별도 단일 스레드 실험 프로세스에서 측정한 값이며,
모든 기기·동시 요청의 3초 응답을 보장하는 수치는 아니다. C 커널은 측정 전 빌드하고 작은 입력으로 1회 초기화했다.
커널이 없으면 NumPy 경로를 사용하며, 같은 속도를 주장하지 않는다.

## 검사판·국소 점검

기존/추가 검사판 15장×세기 3개×모델 4개=180셀. 그룹 평균 대비 하락 0/72셀.
개별 검사판 대비 하락 0/180셀도 별도로 공개한다.
숫자 대비는 점 중심의 숫자/배경 평균 Lab 거리이며, 사람의 숫자 인식 정답률이 아니다.
작품에서 A' 복귀 44/135건, 개별 작품·유형·모델 회복 쌍 하락 1/540셀.
아래에서 평가 입력 해상도의 1:1 잘라보기와 v2 수치를 함께 비교한다.

## v2와의 차이: 회복률 손실도 공개

| 같은 입력·Brettel 전체 회복률 | A' | v2 | v3 | v2→v3 |
|---|---:|---:|---:|---:|
| 기존 21점 | 57.78% | 74.46% | 70.99% | -3.47%p |
| 이전 추가 12점 | 69.25% | 91.73% | 84.47% | -7.27%p |

v2는 평균 ΔE만 제한해 일부 영역에 큰 색 변화를 집중할 수 있었다. v3는 각 픽셀의
원본 대비 변화량도 해당 픽셀의 A' 이하로 제한하고, 손실 쌍의 평균 대비와 큰 색 그룹의
대비가 낮아지는 후보도 제외한다. 반복 횟수도 80회에서 48회로 바뀌었다.
이 여러 변경의 효과를 따로 분해한 실험은 아니므로 회복률 하락을 국소 제한 하나의 영향으로 단정하지 않는다.
수치 조건을 모두 통과했다는 것은 **A'와 사전 기준에 대한 판정**이며, v2보다 모든 면에서 좋아졌다는 뜻이 아니다.

v2의 1000px 최대 5.182초와 v3의 최대 1.293초는 각각의 실행에서 관측한 값이다.
이 값만으로 순수 계산 커널의 속도 향상 배수를 추정하지 않는다. C 계산을 묶고,
학습용 색 변환을 표본에만 적용하고, 탈락 후보를 전체 적용 전에 제거해 비용을 줄였다.

## 개별 하락과 구현 검증

새 작품 `nga-fresh-162261`의 녹색약/Vischeck에서 회복 쌍이 16/26 → 15/26으로 하나 줄었다.
같은 셀의 새 충돌은 30 → 17로 줄었다. 집단별·유형별 조건은 통과했지만 개별 입력의 무하락을 보장하지 않는다.

색 보정·검사판·v1·v2·실행 동등성과 v3 테스트 **총 62개가 통과**했다.
v3의 14개 테스트에는 수치 미분, NumPy/C 목적값·미분 일치, 연속 색 변환의 오차,
부드러운 색 경사, 국소 예산, 표본 사전 검증과 전체 출력의 일치가 포함된다.
A' 계산은 작품 135건과 검사판 45건 모두 기존 함수와 전체 픽셀이 bit-identical이었다.
반복 측정 10건의 최종 출력도 모두 동일했다. 새 Python 파일의 편집기 진단 오류는 없었다.
기존 서버·앱 보정 파일과 라우트는 수정하지 않았다.
